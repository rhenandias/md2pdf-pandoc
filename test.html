Incidente: Incompatibilidade da API do Docker

1. Resumo do Incidente

Após um período de operação contínua de mais de 200 dias (uptime), o servidor EC2 foi reiniciado. Imediatamente após a reinicialização, dois problemas críticos foram observados:

  • O painel do Portainer marcava o ambiente local (Environment) como “Down”, impossibilitando o gerenciamento dos containers.
  • As APIs hospedadas, como a API do ERP Limpeza (limpezaca-api.asisto.com.br), passaram a retornar o erro HTTP 404 Not Found, indicando que o proxy reverso estava inoperante ou incapaz de rotear o tráfego.

Este gráfico exibe o monitoramento de tempo de resposta da API Limpezaca no dia 26 de Junho.

2. Causa Raiz

Durante os mais de 200 dias de uptime, serviços em segundo plano do sistema operacional (Linux) realizaram atualizações de pacotes, incluindo o Docker Engine (que foi atualizado para a versão 29.1.3). No entanto, o serviço do Docker não havia sido reiniciado para aplicar essas atualizações.

Com a reinicialização da máquina, a nova versão do Docker entrou em vigor. A partir da versão 29.0, o Docker introduziu uma mudança estrutural que alterou a versão mínima suportada de sua API local para a versão 1.44.

Isso gerou uma quebra de compatibilidade em cascata:

  • Docker vs Portainer: O cliente interno do Portainer tentava se comunicar usando a API versão 1.41.
  • Docker vs Traefik: O Traefik, responsável por rotear os domínios (reverse proxy), tentava se comunicar usando uma API ainda mais antiga, a versão 1.24 (comum como padrão de retrocompatibilidade em clientes Go).

Como ambas as versões (1.41 e 1.24) eram inferiores ao novo mínimo exigido pelo Docker (1.44), o Docker bloqueou a comunicação de ambas as ferramentas, causando a queda do ambiente.

3. Evidências e Diagnóstico

Diagnóstico do Portainer

Foi executado um teste de comunicação com o socket do Docker simulando a versão exigida pelo Portainer:

curl --unix-socket /var/run/docker.sock http://localhost/v1.41/version

Retorno:

{
  "message": "client version 1.41 is too old. Minimum supported API version is 1.44, please upgrade your client to a newer version"
}

Diagnóstico do Traefik

Para entender o erro 404 da API, foram analisados os logs do container do Traefik:

docker logs traefik-traefik-1 --tail 50

Retorno:

Error response from daemon: client version 1.24 is too old. Minimum supported API version is 1.41

4. Solução Aplicada

Para restabelecer os serviços rapidamente, foi aplicada uma configuração manual no Docker para forçá-lo a aceitar conexões de APIs antigas, englobando as necessidades de ambas as ferramentas.

  • Caminho do arquivo criado: /etc/docker/daemon.json
  • Conteúdo atual do arquivo:
{
  "min-api-version": "1.24"
}

Após a criação do arquivo, o serviço do Docker foi reiniciado (sudo systemctl restart docker). Com a versão mínima ajustada para 1.24, tanto o Traefik quanto o Portainer conseguiram se reconectar ao socket do Docker, e os sistemas voltaram a ficar “Up” e “Healthy”.

6. Próximos Passos e Recomendações

A solução aplicada é temporária e focada na rápida mitigação do incidente. Manter o Docker forçado a suportar APIs desatualizadas (1.24) pode impedir o uso de novos recursos e mascarar a defasagem das ferramentas da infraestrutura.

Ação Recomendada: Planejar a atualização estrutural dos containers do Traefik e Portainer para as versões mais recentes que já utilizem clientes atualizados com suporte à API Docker >= 1.44. Após a validação dessas atualizações, a configuração manual inserida no daemon.json deverá ser removida, restaurando a segurança e o padrão arquitetural do servidor.
